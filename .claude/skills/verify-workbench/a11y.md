# Accessibility check (`a11y.sh`)

Every change made for an accessibility ticket (epic GDB-14287 and its phases) gets this check before it is called
done: the epic's definition of done is "no IBM Equal Access Checker (WCAG 2.2 rule set) violations on the in-scope
pages", so that checker — not axe or Lighthouse, whose rules differ — is the measure. `a11y.sh` injects the IBM
engine into each page of the run's stack and lists the `VIOLATION/FAIL` results; exit 1 means violations.

- Run it on the pages the change touches, in the state the change affects: select a repository with `--repo`, and
  for markup that only renders after an action (a dialog, a menu, a loaded resource tree) bring the page there
  first, or the check passes without seeing the change. Confirm that the changed element is in the DOM.
- Compare with the same pages on master when the result is not clean: report only the violations the change
  introduces or fixes, and list pre-existing ones separately (they belong to other phases' tickets).
- Potential violations and recommendations are in `a11y-report.json` but are not part of the definition of done.
- This is a check, not a test: nothing is added to the repo's specs.
