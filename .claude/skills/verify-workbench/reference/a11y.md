# Accessibility check (`a11y.sh`)

Every change made for an accessibility ticket (epic GDB-14287 and its phases) gets this check before it is called
done: the epic's definition of done is "no IBM Equal Access Checker (WCAG 2.2 rule set) violations on the in-scope
pages", so that checker — not axe or Lighthouse, whose rules differ — is the measure. `a11y.sh` injects the IBM
engine into each page of the run's stack and lists the `VIOLATION/FAIL` results; exit 1 means violations.

- Run it on the pages the change touches, in the state the change affects: select a repository with `--repo`, and
  for markup that only renders after an action (a dialog, a menu, a loaded resource tree) bring the page there
  first, or the check passes without seeing the change. Confirm that the changed element is in the DOM.
- Compare with the same pages on master when the result is not clean: check master on a second container stack
  (same routes, same `--repo` state, same `--viewport`), then `a11y.sh <run-id> --baseline <master-run-id>` lists
  what the change adds (NEW) and fixes (GONE). Report only those, and list pre-existing violations separately
  (they belong to other phases' tickets). Results under `/html/head/style[N]` shift with the index and show up as
  NEW/GONE pairs: ignore them.
- `--viewport WxH` changes the obscured/off-screen results (`element_tabbable_unobscured`):
  check at the viewport the ticket names, and compare runs only at equal viewports (`--baseline` warns otherwise).
- `a11y.sh <run-id> --summary` counts the existing report per route, per level and per rule/level.
- Potential violations and recommendations are in `a11y-report.json` but are not part of the definition of done.
- This is a check, not a test: nothing is added to the repo's specs.

## Report schema (`<evidence root>/<run-id>/a11y/a11y-report.json`)

One entry per checked route, every non-PASS result of the engine:

```json
[{"route": "import", "viewport": "1440x900", "violations": 1,
  "results": [{"level": "VIOLATION/FAIL", "rule": "input_label_exists", "message": "…",
               "xpath": "/html[1]/body[1]/…", "snippet": "<input …>"}]}]
```

- `route` is the argument as given (`""` = home); `violations` counts the `VIOLATION/FAIL` results.
- `level` is `<value[0]>/<value[1]>` of the engine: `VIOLATION/FAIL` (definition of done), `VIOLATION/POTENTIAL`,
  `RECOMMENDATION/MANUAL`, … `rule` is the IBM rule id; `snippet` is cut at 200 characters.
